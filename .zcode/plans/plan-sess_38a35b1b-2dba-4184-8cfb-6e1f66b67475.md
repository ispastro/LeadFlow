## Robust auth page + integration — implementation plan

### Architecture (decisions locked with user)
- Token stays in `localStorage` (key `token`); `lib/auth.ts` becomes the single source of truth.
- Session-expiry handled via a `401 → clearToken + global event → redirect` flow (no middleware/httpOnly rewrite, per user choice).
- Form validation via `zod` + `react-hook-form` + `@hookform/resolvers` (3 new deps).

### New dependencies
`zod`, `react-hook-form`, `@hookform/resolvers` (install with the frontend's existing package manager — npm, per existing `package-lock.json`).

### Files to modify
1. **`frontend/lib/auth.ts`** — keep as single token source; export `TOKEN_KEY`.
2. **`frontend/lib/api.ts`** — remove duplicate `getToken` (import from `lib/auth`); add `ApiError` class with `status`; in `request()`, on `401` call `clearToken()` + dispatch `window` event `auth:unauthorized`, then throw; handle empty `204` bodies safely.
3. **`frontend/lib/queries.ts`** — add `keys.me`; `useCurrentUser()` (getMe, enabled only when token present, retry:false); `useLogin()` (mutation → setToken, prime `keys.me`, clear stale cache); `useLogout()` (call `/api/auth/logout`, clearToken, clear cache, redirect `/login`).
4. **`frontend/app/providers.tsx`** — add `AuthSync` client component listening for `auth:unauthorized`: clear cache + redirect `/login` unless already there.
5. **`frontend/components/auth/AuthGuard.tsx`** — verify session via `useCurrentUser()` (not just token presence); spinner while loading; redirect `/login` when unauthed/expired.
6. **`frontend/app/dashboard/layout.tsx`** — wrap `{children}` with `<AuthGuard>` (the missing wiring).
7. **`frontend/app/login/page.tsx`** — rewrite on zod + react-hook-form, preserving the current design; add field errors + server error banner + password show/hide toggle (lucide Eye/EyeOff); keep demo hint and already-authed redirect.
8. **`frontend/components/dashboard/Header.tsx`** — add current-user email (from `useCurrentUser()`) + Sign-out button (`useLogout()`), styled to match existing header.

### Out of scope (noted, not doing)
- Broken sidebar nav links (`/dashboard/leads` etc.) — unrelated to auth.
- `middleware.ts`/httpOnly cookies — excluded by the chosen architecture.

### Verification (browser-driven after implementation)
Bad creds → inline error; correct creds (`admin@leadflow.com` / `leadflow2024`) → dashboard; visiting `/dashboard` unauthed → bounce to `/login`; Sign out → back to `/login`; simulated token expiry (clear token, trigger a query) → auto-redirect to `/login`.
